# N1 Stock Financial Canonical Incremental Design

Result: DESIGN_PASS

Date: 2026-06-16

Layer role: N1_ingestion

## Problem

The post-close one-shot previously invoked the stock financial canonical source bundle as a full active-universe source probe. On a normal trading day this can scan about 6000 stocks at 18:00, creating a performance bottleneck and leaving the N1 -> N2 -> N3-A1 one-shot in `PARTIAL_BLOCKED` if the source probe is interrupted or too slow.

## Modified N1 Design

N1 stock financial canonical source bundle now uses an incremental snapshot model by default.

New cache artifact:

```text
financial_canonical_snapshot_v1
docs/post_close_fastlane/<for_trade_date>/21_n1_stock_financial_canonical_snapshot_v1.json
```

The snapshot stores:

- `schema_version=financial_canonical_snapshot_v1`
- `source_trade_date`
- active `stock_financial_${source_trade_date}_v1` source version
- full `expected_identity_keys`
- reusable financial source rows
- daily basic rows
- per-symbol `source_signature`
- per-symbol cached financial and forecast rows
- source probe metadata and delta proof

The post-close one-shot now calls the source bundle runner with:

```text
--incremental
--previous-snapshot-path docs/post_close_fastlane/<source_trade_date>/21_n1_stock_financial_canonical_snapshot_v1.json
--snapshot-cache-path docs/post_close_fastlane/<for_trade_date>/21_n1_stock_financial_canonical_snapshot_v1.json
```

It no longer passes the previous daily full-scan flags:

```text
--full-fetch-confirmed
--max-symbols 0
```

## Incremental Pipeline

1. Read the current active N1 financial source rows for `source_trade_date`.
2. Load the previous `financial_canonical_snapshot_v1`.
3. Compute a deterministic per-symbol source signature from report period, announcement date, source type, canonical financial fields, forecast fields, and raw payload.
4. Build the delta set:
   - new symbols missing from the previous snapshot
   - symbols whose source signature changed
   - symbols explicitly passed through `--changed-identity-key`
5. Run external/source probes only for the delta set.
6. Reuse previous cached rows for unchanged symbols.
7. Merge delta rows plus reused rows into a new full `financial_canonical_snapshot_v1`.
8. Feed the new snapshot into the canonical metrics runner.
9. The metrics runner still emits a full active `stock_financial_${source_trade_date}_v2` canonical source, so N2 sees the same full-universe output shape as before.

If the previous snapshot is missing or invalid, incremental mode blocks with:

```text
financial_canonical_snapshot_v1_missing; full rebuild requires explicit --full-rebuild-confirmed
```

This preserves backward compatibility and prevents accidental historical recomputation.

## Determinism And Equivalence

The incremental path is deterministic because:

- delta identity keys are sorted
- signature input is normalized and JSON-hashed with sorted keys
- unchanged rows are copied from the prior snapshot without re-query variance
- changed rows replace previous rows for that symbol only
- the metrics runner recalculates canonical metrics over the merged full snapshot

The intended mathematical equivalence is:

```text
canonical_metrics(full_rebuild(current_sources))
= canonical_metrics(reuse(previous_unchanged_sources) + probe(current_changed_sources))
```

provided the previous snapshot was generated by the same canonical rules and no explicit historical recompute was requested.

## Backward Compatibility

Existing historical snapshots remain valid evidence and are not rewritten.

Legacy source bundle cache format is still accepted by the metrics runner for older reports. New one-shot runs prefer `financial_canonical_snapshot_v1`.

Full rebuild remains possible, but only with explicit operator intent:

```text
--full-rebuild-confirmed
```

No historical recomputation is implied by daily automation.

## Performance Improvement

Before:

```text
18:00 daily source bundle probes about 6000 active symbols.
Runtime and provider/API pressure scale with full universe size.
```

After:

```text
18:00 daily source bundle probes only delta symbols:
new filings + updated reports + changed symbols + explicit changed keys.
Unchanged symbols are read from financial_canonical_snapshot_v1.
```

Expected effect:

- normal no-filing days probe near zero or a small delta set
- filing-heavy days scale with changed symbols rather than all active symbols
- one-shot failure window is much smaller
- N2 still receives full canonical financial coverage

## Safety Boundary

This design change does not authorize:

- N1 DB writes outside the existing canonical metrics execute gate
- N2 recomputation of financial metrics
- N3-B/C/B2
- N4/N5/N6
- outbox/inbox/checkpoint consumption or status update
- worker startup
- delivery/push/voice/mobile
- sim/position/pnl/real_trade
- proposal/order/trade

## Recommended Operational Rule

Daily post-close automation should run incremental mode by default.

If the snapshot seed is missing, do not silently scan the full market. Create or approve a separate seed/full-rebuild run with `--full-rebuild-confirmed`, then resume daily incremental automation.
